# Environment and credentials — what the v5.8 flow needs (no secret values in this file)

Two places hold configuration, and nothing else may.

## 1. n8n node `00 CONFIG (single point)` (child workflow `034iqKMRjqKt9LlB`)

Every downstream node reads this Set node; no other node carries an endpoint or a key.

| Assignment | Meaning | Example / shape | Secret? |
|---|---|---|---|
| `doc_id` | paperless document id; `={{ $json.doc_id \|\| ($json.body && $json.body.doc_id) \|\| 89 }}` when called by the parent | integer | no |
| `paperless_url` | paperless-ngx base URL (the flow's `Get a document` node uses it) | `http://<dms-host>` | no |
| `paperless_token` | paperless API bearer token | **`<<PAPERLESS_TOKEN>>`** | **yes** |

when importing to another instance.

`PAPERLESS_BASE_URL`, `PAPERLESS_API_TOKEN`, `LITELLM_URL`, `LITELLM_API_KEY`, `MODEL_VISION`,

`SYSTEM_A_AI_MODE=live`, so every parity claim compares the port against the same live services.

## Rules that keep secrets out of git

- `tools/n8n_port/.gitignore` excludes `live/`, `dist/`, `fixtures/`, `n8n_nodes/port_config.json`,
  `nodes/`, `blackbox.json`, `parent_dump.json` — the files that carry tokens or real invoice data.
  Verified with `git check-ignore -v` and `git add -n`: the first version of that block wrote the
  explanation as a *trailing* comment on each pattern line, git read it as part of the pattern, and the
  rules matched nothing (a `#` only starts a comment at line start). Comments now sit on their own lines.
- `harness/export_workflow.py` redacts recursively (the canvas API also embeds the *published* copy of
  every node) and **refuses to write** if any collected secret value survives.
