# OCR Pipeline Accuracy Enhancement & BBox Fidelity Implementation Plan

> **For Antigravity:** REQUIRED WORKFLOW: Use `.agent/workflows/execute-plan.md` to execute this plan in single-flow mode.

**Goal:** Eliminate false-negative rule failures (V-01, V-03, V-06, V-07) across pure scanned invoices in `run_clean_all` by enhancing Date & Money Normalizers, Warehouse Receiving Stamp detection on Delivery Notes, Grand Total reconciliation, and Middle-block Table Collapsing, without mutating bounding box coordinates or Result Contract schemas (`result-3.0.schema.json`).

**Architecture:** 
1. **Deterministic Normalizer Hardening (`normalize.py`):** Add multi-lingual month name parsing (`Jan`..`Dec`, `ม.ค.`..`ธ.ค.`) to `date_iso()`, and strip Thai currency zero-satang notation (`.-`, `-`) in `split_number()` while strictly preserving field bounding boxes.
2. **Delivery Note Stamp & Signature Recognition (`vision_pipeline.py` & `normalize.py`):** Map warehouse receiving stamps (`label: 'received_stamp'`, `'receiving_stamp'`) on `DELIVERY_NOTE` pages into `signatures.receiver` with its exact detected bbox.
3. **Grand Total Arithmetic Reconciliation (`vision_pipeline.py`):** Detect cases where Grand Total repeats Subtotal, search candidate pools for `sub_total + vat`, and derive `grand_total = s + v` when line arithmetic and 7% VAT are internally sound.
4. **Middle-Block Duplicate Table Folding (`evidence.py`):** Expand `collapse_duplicate_block` to eliminate duplicated table blocks occurring in the middle of multi-page invoices (e.g. DMS-26).

**Tech Stack:** Python 3.11, Pydantic, PyMuPDF, Pytest, Regex.

## Proposed Changes

### Component 1: Deterministic Normalizers (`src/system_a/domain/normalize.py`)

#### [MODIFY] `src/system_a/domain/normalize.py`
- In `date_iso(raw: str)`:
  - Add support for textual English month names and abbreviations (`Jan`, `Feb`, `Mar`, `Apr`, `May`, `Jun`, `Jul`, `Aug`, `Sep`, `Oct`, `Nov`, `Dec`) and Thai months (`ม.ค.`..`ธ.ค.`).
  - Correctly map dates such as `"4 Sep 2026"` and `"07-SEP-2026"` into ISO format `"YYYY-MM-DD"`.
- In `split_number(raw: str)`:
  - Strip trailing `.-` and `-` representing zero satang (e.g. `"3,000.-"` $\rightarrow$ `"3000.00"`) prior to numeric validation.

### Component 2: Warehouse Receiving Stamp Recognition (`src/system_a/perception/vision_pipeline.py` & `normalize.py`)

#### [MODIFY] `src/system_a/perception/vision_pipeline.py`
- Add `"received_stamp": "receiver"`, `"receiving_stamp": "receiver"`, `"receiver_stamp": "receiver"` to `SIGNATURE_LABELS`.
- In `_fields()`: Allow receiver signature slots to be populated from `reads[p].items` across all pages (including `page_type == 'DELIVERY_NOTE'`), populating `signatures['receiver']` with its exact bbox and confidence.

#### [MODIFY] `src/system_a/domain/normalize.py`
- Add `_receiver_from_stamp(ext, std, sigs)` alongside `_deliverer_from_stamp`:
  - When receiver signature is undecided, inspect `ext.regions` or stamps on `DELIVERY_NOTE` pages for `received_stamp`.

---

### Component 3: Grand Total Arithmetic Reconciliation (`src/system_a/perception/vision_pipeline.py`)

#### [MODIFY] `src/system_a/perception/vision_pipeline.py`
- In `reconcile_grand_total(fields, candidates, log)`:
  - If `abs(s + v - g) > 0.01` and `abs(s - g) <= 0.01` (Grand Total mistakenly duplicated Subtotal):
    - Search all money candidates for `target = s + v`.
    - If found, assign candidate's value and bbox to `grand_total`.
    - If no distinct candidate exists but line items and 7% VAT are internally sound, assign `grand_total = s + v` using the grand total region with agreement `True`.

---

### Component 4: Middle-Block Duplicate Table Folding (`src/system_a/domain/evidence.py`)

#### [MODIFY] `src/system_a/domain/evidence.py`
- In `collapse_duplicate_block(doc, snap, std)`:
  - Extend search from only checking tail blocks `sigs[n - m:]` to checking arbitrary slice pairs `sigs[i : i + m] == sigs[j : j + m]` where dropping the duplicate block causes sum of lines to equal `sub_total` or `receipt_total`.
